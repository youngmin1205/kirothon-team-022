# product.md 스키마 (템플릿 v3)

`deliverables/product.md`에는 JSON 블록이 두 개 있다. `npm run sync`가 이 블록을 읽어 영상과 슬라이드에 넣는다.

## ```json film``` 블록

| 필드 | 형식 | 쓰는 곳 | 작성 요령 |
|---|---|---|---|
| `service` | 문자열 | 모든 장면 상단, 로고 옆 | 서비스 이름. 8자 안팎 |
| `logoIcon` | Lucide 아이콘 이름 | 제품 공개, 마무리 | 예: `Pill`, `ShieldCheck`. https://lucide.dev/icons 에 있는 이름만 |

### 단계 (`demo.steps[]`)
공통 필드는 `id`(capture.beats의 id와 같아야 함), `label`(왼쪽 흐름에 보일 2~5자), `icon`(Lucide), `title`(팝업 제목)이다. 핵심 장면 한 곳에만 `"key": true`를 붙인다. 팝업 내용은 아래 중 하나를 고른다.

| 필드 | 형식 | 어울리는 단계 |
|---|---|---|
| `lines` | 문자열 배열 | 시작, 알림 |
| `items` (+ `note`) | `[[이름, 태그], …]` | 판독 결과, 복기 |
| `checks` | 문자열 배열 | 사람 확인 |
| `quote`, `sourceLabel`, `source` | 문자열 | 근거 안내, 대사 |
| `rules` | `[[행동, 결과, "ok"\|"bad"], …]` | 권한 검사, 차단 |
| `status` | `[[항목, 값, "ok"\|"wait"], …]` | 공유, 학습 결과 |
| `meters` (+ `note`) | `[[지표, 0~100], …]` | 실시간 위험도, 점수 |

### 축하 (`demo.celebrate`)
사용자가 핵심 행동을 끝낸 순간에 화면이 3초 멈추고, 선물 상자가 터지며 컨페티와 효과음이 나온다.

| 필드 | 예시 |
|---|---|
| `at` | `capture.beats`의 id 하나 (그 순간에 터짐) |
| `title`, `sub` | `"아침 약 완료!"`, `"07:32 · 3알 모두 드셨어요"` |
| `badge` | `{ "icon": "Flame", "pre": "", "from": 2, "to": 3, "post": "일 연속 복약" }` |
| `track` | `{ "labels": ["월","화","수","목","금","토","일"], "done": 2 }` (done 번째 칸이 이번에 채워짐) |
| `goal` | `"이번 주 개근 배지까지 4일"` |

## 8구간 (본선 3분 30초 기준)
| # | 구간 | 시간 | 심사 축 |
|---|---|---|---|
| 1 | 오프닝 | 15초 | 가치 |
| 2 | 문제 | 30초 | 가치 |
| 3 | 해결 한 문장 | 15초 | 독창성 |
| 4 | 라이브 데모 | 70초 | 가치, 완성도 |
| 5 | 믿을 수 있는 이유 | 15초 | 완성도 |
| 6 | 작동 방식 | 20초 | 구현 |
| 7 | Kiro로 만든 방식 | 30초 | Kiro 활용 |
| 8 | 다음 단계와 클로징 | 15초 | 가치 |

3분이면 5번과 6번을 15초씩 줄이고, 4분이면 데모에 예외 상황을 30초 더한다.

## ```json capture``` 블록

| 필드 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `url` | 예 | | 녹화할 주소. 상대 경로면 `deliverables/` 기준 파일 경로. 실행할 때 `DEMO_URL`이 있으면 그쪽이 우선 |
| `device` | 아니요 | `"phone"` | `"phone"`: 휴대폰 화면만 잘라 휴대폰 프레임에 넣음. `"browser"`: 브라우저 창(1600×1000) 전체를 브라우저 프레임에 넣음. 웹 서비스면 `"browser"` |
| `screen` | 아니요 | phone이면 `".phone .screen"`, browser면 없음(창 전체) | 잘라 낼 화면 영역의 선택자 |
| `pin` | 아니요 | `".phone"` | phone 모드에서 좌상단에 2배로 고정할 요소 |
| `play` | 아니요 | `"#play"` | 누르면 데모 흐름이 자동으로 진행되는 버튼 |
| `beats` | 예 | | `[{ "id", "sel", "caption" }, …]`. `sel`이 나타나야 다음으로 넘어감. 마지막은 `"end"` |
| `beats[].focus` | 아니요 | `sel`과 같음 | 카메라가 확대해서 비출 요소. `sel`이 목록의 마지막 줄처럼 작은 요소라면, 그 줄을 담은 카드나 목록 전체를 적는다 (예: `"#risks"`) |
| `beats[].tap` | 아니요 | `false` | `true`면 그 순간 커서(browser) 또는 터치 표시(phone)가 요소로 이동해 누른다. 사용자가 실제로 누르는 단계에만 붙인다 |

### 카메라 (v5.1)
녹화할 때 단계마다 `focus` 요소의 위치와, 그 요소를 담은 콘텐츠 묶음(창 너비의 3/4 안에 드는 가장 넓은 상위 요소)의 좌우 범위를 기록한다. 영상은 이것으로 차분하게 확대한다.
- browser 모드에서만 확대한다. phone 모드는 화면이 이미 크므로 확대하지 않고, `tap` 표시만 쓴다.
- 확대는 최대 1.45배이고, 콘텐츠 묶음을 좌우 끝까지 담아서 옆 칸이 어중간하게 잘리지 않게 한다.
- 대상이 이미 화면 안에 있거나 직전 이동 뒤 2.5초가 안 지났으면 카메라를 움직이지 않는다.
- 녹화 위에 강조 테두리를 그리지 않는다. 앱 화면이 계속 움직여서 테두리가 대상에서 어긋나기 때문이다.
- browser 모드에서는 요소가 창 아래에 있으면 페이지를 자동으로 스크롤한다. 목업 사본을 만들어 스크롤 코드를 넣을 필요가 없다.
