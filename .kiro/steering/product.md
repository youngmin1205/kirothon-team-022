## 한 줄 소개

<!-- 예: "AI 사기꾼이 훈련 전화를 걸어, 넘어가는 순간 화면을 멈추고 복기한다" -->

**밥은 먹었니** — 사진 한 번, 기분 버튼 하나로 엄마·아빠에게 각자 맞는 안부가 가고, 부모님은 설치 없이 버튼으로 답한다

## 사용자 · 문제 · 해결

- **사용자:** 부모님과 떨어져 사는 자취 직장인(앱 사용)과 그 부모님(설치 없음, 카톡·문자로 받음)
- **문제:** 부모님은 매일 "밥 먹었냐, 집에 들어갔냐"를 묻고, 자녀는 같은 답을 매일 치기 귀찮아서 늦게 답하고, 그 사이 부모님은 걱정한다
- **해결 (최소 데모 버전):**
  - 자녀가 사진 1~3장을 올리고 기분 버튼을 누른다. AI는 사진으로 **밥·귀가만** 판정하고, 자녀가 칩을 확인·수정한다
  - 받는 사람 프로필(미리 넣어 둔 JSON)에 따라 공개 항목과 말투가 다른 메시지를 사람마다 만든다
  - 부모님은 카톡·문자 **본문만 봐도** 안부를 안다. 링크는 사진 크게 보기와 답하기 때만 연다
  - 부모님은 링크 페이지의 **고정 버튼**으로 반응하고 자기 안부도 보낸다

### 고정 규칙 (spec 수락 기준의 근거)

- 안부 항목은 `밥 / 귀가 / 기분 / 한마디` 넷으로 고정한다. 그 밖의 대화는 원래대로 카톡·전화로 한다
- 기분 버튼: 😊 좋아 · 🙂 괜찮아 · 😪 피곤해 · 😵 바빠 · 🤒 아파 + ✏️ 직접 입력. **AI가 기분을 판정하지 않는다.** 직접 입력 문장은 뜻을 바꾸지 않고 말투만 다듬는다
- 부모님 버튼: ❤️ 잘 받았어 · 📞 전화할게 · 🍚 나도 밥 먹었어 · 🏥 병원 다녀왔어 · 🙂 오늘 괜찮아
- 받는 사람 프로필 예: 엄마 = 밥·귀가·기분, 다정하게 / 아빠 = 귀가만, 짧게
- **프로필에 없는 항목은 코드가 먼저 걸러낸 뒤 모델에 넘긴다.** 프롬프트로 막지 않는다 (테스트: 아빠 메시지에 기분 언급 0건)
- 메시지 본문에 항목 요약을 그대로 넣는다. 예: `민지 오늘 안부 🍚 점심 김치찌개 먹음 · 🏠 9시 귀가 · 🙂 조금 피곤 / ❤️ 답하기 ▶ 링크`

## 데모 구간 (가장 중요)

> 여기서 "데모"는 제품의 **핵심 사용 흐름(happy path)** 을 말한다. 사용자가 앱을 열어서
> 끝까지 가는 경로를 단계로 쪼갠 것이다. 코드와 녹화 도구에서는 `beat` 라고 부른다.
>
> **이걸 먼저 정하는 이유는 서로 기다리지 않기 위해서다.** 단계 이름과 문구가
> `mock.json` 에 먼저 들어가면, 프런트는 백엔드 로직 없이 화면을 끝까지 만든다.

흐름은 `#play` 버튼 하나로 처음부터 끝까지 자동 재생되어야 한다. 아래 단계 id 가
**네 곳에서 같은 이름으로 쓰인다.** 그래서 여기만 정하면 나머지가 따라온다.

| 쓰이는 곳 | 어떻게 |
|---|---|
| 화면 | `data-beat="<id>"` + `data-state="pending\|active\|done"` |
| 서버 | `backend/features/<기능>/mock.json` 의 `beats[].id` |
| 자동 검증 | `pnpm smoke` 가 구간이 순서대로 done 이 되는지 확인 |
| 영상·슬라이드 | `deliverables/product.md` 의 `capture.beats[].id` |

구간은 6~8개로 한다. 더 많으면 데모가 길고, 적으면 이야기가 안 된다.

**이 표를 먼저 채우고 `mock.json` 에 단계별 문구를 넣으면, 기능이 하나도 없는
상태에서도 흐름이 완주한다.** 그러면 프런트가 백엔드를 기다리지 않는다.

> 한계: 이 구조는 순차적인 흐름을 가정한다. 대시보드형이나 배치 처리형이면
> 억지가 되므로 느슨하게 쓰거나 버린다.

`사용자 발화` 는 그 구간 직전에 사용자가 하는 말이다. `mock.json` 의 `say` 가 되고, live 녹화에서
`#play` 가 이 문장을 실제 모델에 보낸다. 1번은 시작 화면이라 비운다.

| # | id | 사용자 발화 (say) | 화면에 보이는 것 | 담당 |
|---|---|---|---|---|
| 1 | `home` | — | 자녀 폰: 오늘 안부 보낼 사람 엄마 · 아빠 | 세민 |
| 2 | `upload` | 점심이랑 현관 사진 올릴게, 오늘 좀 피곤해 | 사진 2장 첨부 + 기분 버튼 "😪 피곤해" 선택 (✏️ 직접 입력칸도 보임) | 세민 |
| 3 | `judge` | 이 사진으로 오늘 안부 정리해 줘 | AI 칩: 밥 ✓(김치찌개) · 귀가 ✓(21시) | 채연 |
| 4 | `confirm` | 맞아, 이대로 보내 | 자녀가 칩 확인·수정 | 세민 |
| 5 | `compose` | 엄마랑 아빠한테 보낼 메시지 만들어 줘 | 엄마용 / 아빠용 메시지 미리보기가 나란히 (항목·말투가 다름) | 채연 |
| 6 | `deliver` | 보내기 | 부모님 폰: 메신저 말풍선에 요약 본문 + 링크 미리보기 카드 | 세민 |
| 7 | `react` | (엄마) 나도 밥 먹었어 | 엄마가 링크를 열어 ❤️ + "🍚 나도 밥 먹었어" | 세민 |
| 8 | `reply` | — | 자녀 폰: "엄마도 밥 드셨대요" 칩 (celebrate) | 세민 |

## 당일 고정 규칙 (아이디어와 무관)

아래는 주제가 무엇이든 지킨다.

- **데모 경로 하나를 끝까지 완주시키는 것이 최우선이다.** 곁가지 기능보다 완주가 먼저다
- **mock 은 비상용이다.** `USE_MOCK=1` 로 Bedrock 없이 전 구간이 재생되어야 한다.
  최종 녹화는 live(실제 모델)로 하고, 실패하면 mock 으로 대체한다. 무대 시연은 mock 으로 한다
- **`mock.json` 의 구간마다 `say`(사용자 발화)를 채운다.** live `#play` 가 이 문장을 모델에 보낸다
- **통합 체크포인트에서 데모가 돌아야 한다** (11:30 / 13:00 / 15:30 / 16:30).
  안 돌면 기능을 더 붙이지 않고 그것부터 고친다
- **17:00 이후 기능 추가 중단.** 버그와 데모 안정화만
- 범위를 줄이는 결정은 lead 가 한다. 에이전트가 임의로 기능을 늘리지 않는다
