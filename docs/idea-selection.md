## 공식 심사 배점

| 항목 | 1차 (전체 팀, 18:00 레포를 AI가 평가) | 결선 3팀 |

| Kiro 활용 | 35 | 20 |

| 문제 정의 | 20 | 25 |

아이디어 단계에서 보는 법
- **Kiro 활용**: 대부분 과정 점수(BUILD_REPORT·.kiro/). 아이디어 쪽에선 spec 수락 기준·테스트·hooks를 자연스럽게 쓸 만큼 요구사항이 분명한지
- **작동**: 6시간 안에 처음부터 끝까지 확실히 돌아가는지 (실패 위험 요소)
- **문제 정의**: 사용자·문제가 구체적이고 주제("매일 겪는 작은 불편, 나와 주변 사람")에 맞는지
- **사용자 가치**: 바로 쓸 수 있는지, 얼마나 덜어주는지

## 근거

**오늘 뭐 시켜**
- Kiro 3: "나도·취소·아까 그거" 이벤트 → 최종 주문 계산이 수락 기준으로 딱 떨어짐. 계산은 순수 코드라 spec → 테스트 → hooks 자동 실행 흐름이 BUILD_REPORT에 그대로 남음
- 작동 3: 텍스트 입력, 숫자는 코드가 계산해서 라이브에서도 같은 결과
- 문제 3: 매일, 막내·총무라는 구체 사용자, 손으로 세다 틀림
- 가치 2: 주문 모으는 1명에게 효과가 크지만, 배달앱 함께주문·카톡 투표 같은 대안이 있음 → 차별점(단톡 그대로 붙여넣기)을 README에 분명히

**밥은 먹었니** (최신 논의안: 사진 → 밥·귀가·컨디션 → 카톡·문자, 부모님 설치 없음)
- Kiro 2: 앱이 작고 핵심이 프롬프트라 spec·테스트로 보여줄 게 적음
- 작동 2: 사진 판정이 틀리면 데모가 무너짐
- 문제 3 / 가치 3: 매일, 나+부모님, 공감 최고. 결선 심사(문제·가치 50점)에서 강함
- 주의: `idea-cards.md` 카드 문구는 아직 부모님 화면(❤️·📞) 버전

**손들기**
- Kiro 3: 참가자·진행자 두 화면, 단계별 집계, 에러 묶기 → spec 풍부
- 작동 2: 두 화면 동기화(뼈대에 없음, 폴링으로 가능) + AI 에러 묶기 품질. 목업 범위(체크인·QR·설정·CLI 수집)가 넓어서 줄여야 함
- 문제 2: 문제는 아주 구체적이지만 **주제 "매일 겪는 일상의 불편"과 연결이 약함** (실습은 매일이 아님). 목업의 "오늘의 상태(가족·팀 체크인)"는 주제에 억지로 붙인 느낌이라 범위만 늘림
- 가치 2: 진행자 가치는 큼. 일상 적용은 약함
- 강점: 심사·운영진이 실습을 여는 커뮤니티(AWSKRUG·AUSG)라 결선 공감은 클 수 있음 (점수엔 안 넣음)

**살까 말까**
- 문제 2: 매일 겪는 "불편"보다 유혹에 가까움. 캡처 추출 실패 위험(작동 2)
