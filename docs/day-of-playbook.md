## 0. 전날 — 전원 반드시

각자 자기 노트북에서 돌립니다. **하나라도 실패하면 당일 아침에 그만큼 날아갑니다.**

```bash
git fetch origin
git switch main                   # 당일 작업 브랜치 (rehearsal/h-phishing 내용을 그대로 합침)
git pull --rebase --autostash

pnpm smoke          # "smoke 통과" 가 나와야 합니다
```

네 줄이 각각 무엇을 하는지:

| 명령 | 하는 일 | 왜 필요한가 |
|---|---|---|
| `git fetch origin` + `git switch main` + `git pull` | 팀이 올린 **코드와 설정**을 받고 **당일 작업 브랜치(`main`)로 옮깁니다** | 레포에는 우리가 쓴 코드만 있습니다. 옛 `rehearsal/h-phishing` 에 있던 사람도 `main` 으로 옮겨야 같은 코드를 봅니다 |
| `pnpm bootstrap` | 코드가 쓰는 **외부 라이브러리**를 받습니다 (React, FastAPI, boto3 등) | 라이브러리는 git에 없습니다. `package.json`·`pyproject.toml` 의 목록을 보고 내려받습니다 |
| `./scripts/preflight.sh` | **내 PC가 준비됐는지 점검**합니다. 런타임 버전, kiro-cli 버전과 에이전트 로딩, `.env`, 비밀키 | 실패 항목만 알려줍니다. AWS 를 호출하지 않습니다 |

### AWS · Bedrock 준비 (전날 반드시, 각자)

**전제: Bedrock 으로 갑니다.** 주최 측 계정을 받든 못 받든, **전날 각자 개인 계정으로 아래 6단계를 끝내 둡니다.** 그러면 당일 AWS 때문에 막히지 않고, 계정을 받으면 `.env` 의 (B) 블록만 바꿔 끼우면 됩니다.

이미 개인 계정과 프로필이 있는 사람은 **5~6단계만** 확인하면 됩니다.

#### 1. AWS 가입

카드(신용·체크)와 전화 인증이 필요합니다. 가입 자체는 무료이고 Bedrock 은 사용량 과금입니다. 당일 호출량은 `MAX_TOKENS=1024` 에 수백 회 규모라 큰 금액이 아닙니다.

#### 2. Bedrock 콘솔에서 Claude 열기 → **Anthropic FTU 양식 작성**

리전을 **us-west-2** 로 맞추고 Bedrock 콘솔의 모델 카탈로그에서 Claude 계열을 엽니다.

- **Anthropic 모델은 최초 1회 "First Time Use(FTU)" 양식**을 작성해야 호출됩니다. 이게 가장 자주 빠뜨리는 단계입니다
- 첫 호출 시 Marketplace 구독이 백그라운드로 시작되고 **정착에 최대 15분**이 걸립니다. 그 사이에는 `AccessDeniedException` 이 날 수 있습니다 → **당일 아침에 하면 안 되는 이유가 이 15분입니다**
- 계정에 **유효한 결제 수단**이 등록돼 있어야 구독이 완료됩니다

> 근거: [AWS 공식 문서 — Request access to models](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)
> (내용은 라이선스 준수를 위해 요약했습니다)

#### 3. 자격증명 등록

```bash
aws configure --profile hackathon      # Access Key / Secret / region=us-west-2
# SSO 를 쓰면: aws sso login --profile hackathon
aws sts get-caller-identity --profile hackathon    # 계정이 찍히면 성공
```

#### 4. `.env` 의 (A) 블록 채우기

```bash
cp .env.example .env     # 이미 있으면 건너뜁니다
```

```bash
AWS_PROFILE=hackathon
AWS_REGION=us-west-2
USE_MOCK=0
```

`.env` 는 `.gitignore` 에 있습니다. **커밋되지 않으므로 각자 자기 노트북에서 채웁니다.**

#### 5. 쓸 수 있는 모델 확정

```bash
./scripts/aws-check.sh --invoke
```

계정 확인 → 리전 3곳(us-west-2 · us-east-1 · ap-northeast-2) 조회 → Sonnet 우선으로 **최대 4개를 실제로 1회씩 호출** → 성공한 ID 확정 순으로 돕니다. 마지막에 두 줄이 출력됩니다.

```
AWS_REGION=us-west-2
BEDROCK_MODEL_ID=us.anthropic.claude-...
```

이 두 줄을 `.env` 에 반영합니다. **"사용할 모델 확정"** 이 보여야 통과입니다.

막히면 메시지를 보고 대응합니다.

| 증상 | 원인 |
|---|---|
| `자격증명이 동작하지 않습니다` | 3단계 미완. SSO 면 `aws sso login` |
| `어느 리전에서도 Claude 모델을 찾지 못했습니다` | 2단계 미완 (FTU 양식 또는 결제 수단) |
| `호출에 성공한 모델이 없습니다` | 구독 정착 대기 중일 수 있음. 15분 뒤 재시도 |

#### 6. 앱에서 실제로 대화해 보기

```bash
pnpm dev        # localhost:5173
```

입력창에 아무 말이나 치고 **답이 오는지**, 개발 바의 칩이 **`Bedrock`** 인지 봅니다. 칩이 `고정 시나리오` 면 `.env` 의 `USE_MOCK` 또는 `BEDROCK_MODEL_ID` 가 비어 있습니다.

> ✅ **6단계까지 되면 전날 AWS 준비는 끝입니다.** 결과(되는지 / 안 되는지)를 팀 채널에 공유하세요.

### AWS 는 어디까지 필요한가

| 용도 | 자격증명 필요 |
|---|---|
| 앱 실행 (`pnpm mock`) | **불필요** |
| 데모 **녹화** | **필요** (live 가 기본값. 실패하면 mock 으로 대체) |
| 무대 시연 | 불필요 (mock 으로 돌림. 네트워크 리스크) |
| 배포 | 불필요 (로컬 또는 터널) |
| `pnpm smoke` · `pnpm check` | **불필요** |
| **실제 LLM 호출 (`pnpm dev`)** | **필요** |

**EC2 같은 다른 서비스는 쓰지 않습니다.** Bedrock 하나뿐입니다.

개발 중 화면 확인은 입력창으로 하고(`pnpm dev`), **최종 녹화는 live(실제 모델)로** 합니다. 행사의 핵심 가치가 "실제로 동작하는 결과물"이라서입니다. `mock.json` 각 구간의 `say` 를 `#play` 가 모델에 보내므로 대본대로 찍힙니다.

mock 은 **비상용**입니다. live 녹화가 실패하거나 무대 네트워크가 불안할 때 `USE_MOCK=1` 로 같은 `#play` 를 돌립니다. 그래서 **제출물은 자격증명 없이도 만들 수 있게** 설계해 둔 상태는 그대로입니다.

### 아이디어 카드는 한 파일에 모읍니다

**각자 따로 채점하면 안 됩니다.** 채점이 상대 비교라서 같은 파일에 다 모여 있어야 순위가 나옵니다.

실무적으로는 각자 자기 카드를 팀 채널에 붙이고 **lead가 `docs/idea-cards.md` 에 모아 붙이는 쪽**이 빠릅니다. 한 파일을 셋이 동시에 고치면 충돌이 납니다.

그다음 명령 한 줄입니다. "비교해줘" 같은 말을 따로 할 필요가 없습니다.

```bash
./scripts/score-ideas.sh      # 결과 → docs/idea-selection.md
```

스크립트가 `idea-scoring.md` 의 채점 기준·뼈대 목록과 카드 전체를 합쳐 kiro-cli 로 한 번 돌립니다.

### `mock.json` 을 먼저 커밋하는 이유

**이게 병렬 작업의 출발점입니다.** 11:25에 product.md 를 push 한 직후 lead가 단계 id와 문구를 넣고 push하면, 프런트 담당은 **백엔드 로직 없이 화면을 끝까지 만들 수 있습니다.** 서버가 그 문구를 돌려주기 때문입니다.

이걸 안 하면 프런트가 백엔드 완성을 기다립니다. 6시간에서 그 대기 시간이 가장 아깝습니다.

`mock.json` 에 필요한 건 `product.md` 의 **구간 id 와 문구뿐**이라 spec 을 기다릴 이유가 없습니다. spec 이 끝나는 11:40 까지 기다리면 FE/BE 가 25~30분을 놉니다.

### `전원 pull → pnpm smoke` 를 하는 이유

내 PC에서 되는 것은 확인이 아닙니다. **남의 코드를 받은 뒤에도 도는지** 봐야 합니다. `pnpm smoke` 가 서버를 띄우고 `#play` 를 눌러 단계가 순서대로 끝나는지 자동으로 확인합니다.

### 체크포인트 규칙 (가장 중요)

**체크포인트에서 `pnpm smoke` 가 실패하면, 새 기능을 붙이지 말고 그것부터 고칩니다.**

```bash
git pull --rebase --autostash && pnpm smoke
```

이유가 둘입니다.

- 데모가 안 도는 상태로 기능을 쌓으면, 17:00에 "어디서 깨졌는지" 찾느라 시간을 다 씁니다
- 항상 도는 상태를 유지하면 **어느 시점에 멈춰도 제출할 것이 있습니다**

통과한 상태만 커밋합니다. 그러면 "어제까지 되던 게 안 된다"가 없어집니다.

### 11:25 · `mock.json` 선push (L)

**product.md 를 push 한 직후 바로 합니다. 이게 병렬 작업의 출발점입니다.** spec 을 기다리지 않습니다 — 필요한 건 product.md 의 구간 표뿐입니다.

**손으로 쓰지 않습니다.** 이미 띄워 둔 `kiro-cli --agent build` 에 한 줄 던집니다.

```
product.md 의 데모 구간 표로 backend/features/<기능>/mock.json 을 만들어줘.
id·say 는 표 그대로 (1번은 say 없음), text 는 "화면에 보이는 것"을 응답 문장 하나로, data 는 {}, delayMs 는 700.
sample/mock.json 형식을 따르고, 다 만들면 pnpm smoke 를 돌려줘.
```

결과는 이런 모양입니다.

```json
{ "beats": [
  { "id": "intro", "text": "첫 응답", "delayMs": 700, "data": {} },
  { "id": "hook", "say": "사용자가 하는 말", "text": "그에 대한 응답", "delayMs": 700, "data": {} }
] }
```

push 전에 두 가지만 눈으로 봅니다.

- beat id 가 `product.md` 의 구간 id 와 **철자까지** 같은가. 다르면 `pnpm smoke` 가 못 찾아 실패로 뜨거나 녹화가 그 지점에서 멈춥니다
- 2번 이후 구간에 `say` 가 다 있는가. 비면 live 녹화에서 `"다음"` 이 가서 모델이 대본과 무관하게 답합니다

`data` 의 숫자는 이후 BE/FE 가 화면을 만들며 채웁니다.

## 2. 역할 — 두 가지를 구분하세요

섞이기 쉬운 두 축입니다.

| 축 | 무엇 | 개수 |
|---|---|---|
| **Kiro 에이전트** | `build` · `review`. 도구 프리셋입니다 | 2개 |
| **사람 담당** | 누가 어느 폴더를 쓰나 | 3명 |

**셋 다 `kiro-cli --agent build` 로 작업합니다.** 에이전트는 사람별로 나누지 않습니다. 레이어별 규칙은 `frontend.md`·`backend.md` steering 이 건드리는 폴더에 따라 자동으로 붙습니다. `review` 는 누구나 통합 전에 별도 세션으로 띄웁니다.

### 사람 담당

| 사람 | 라벨 | 하는 일 | 쓰는 폴더 |
|---|---|---|---|
| 영신 | **L** | 주제 기록, 선정 진행, product.md, spec, `mock.json` 선커밋, 통합, 제출. 여력이 있으면 에이전트 프롬프트도 | 공용 파일 전부 |
| 채연 | **BE** | 백엔드 + 에이전트 프롬프트·도구 | `backend/features/<기능>/` |
| 세민 | **FE** | 프런트 + 발표 산출물 | `frontend/src/features/<기능>/`, `deliverables/` |

> 역할은 사전에 팀과 확정하세요. 위는 지금까지 올라온 작업물 기준 제안입니다.
> `.kiro/specs/` 의 task 라벨도 **L · BE · FE 세 개만** 씁니다.

**공용 파일은 lead만 고칩니다**: `backend/main.py`, `backend/core/`, `frontend/src/app/`, `frontend/src/ui/`, `frontend/src/types/api.ts`, `.kiro/steering/product.md`

겹치면 먼저 말합니다. 3명이 각자 clone으로 일하므로 충돌은 `git pull --rebase` 시점에 납니다.

## 3. 명령어 치트시트

```bash
# 개발
kiro-cli --agent build              # 셋 다 이걸로 작업
pnpm dev                            # 입력창으로 직접 대화하며 개발 (실제 모델, AWS 호출)
pnpm mock                           # 고정 시나리오 재생 (Bedrock 없음) → localhost:5173

# 확인
pnpm smoke                          # 데모 완주 자동 확인 (체크포인트마다)
pnpm check                          # lint · 타입 · 테스트

# 리뷰 (별도 세션)
kiro-cli --agent review "방금 변경사항 리뷰해줘"

# 제출물
pnpm build && pnpm start            # 단일 프로세스로 전체 서빙
npm --prefix deliverables run capture   # 영상 (담당3, macOS)
npm --prefix deliverables run ppt       # 슬라이드 (담당3, macOS)
```

### `pnpm mock` 을 열면 무엇이 보이나

브라우저에서 `localhost:5173` 을 여는 **웹앱**입니다. 네이티브 앱이 아닙니다.

```
┌─ 개발 바: 서비스 이름 · [고정 시나리오] 칩 · [데모 재생] [처음으로] ──┐
│                                                                       │
│                      ┌──────────────┐                                 │
│                      │  휴대폰 틀    │   ← 기본은 제품 화면만          │
│                      │  대화 버블    │                                 │
│                      │ [입력창][보내기]│  ← 여기에 직접 칩니다          │
│                      └──────────────┘                                 │
└───────────────────────────────────────────────────────────────────────┘

?showcase=1 을 붙이면 오른쪽에 계측 패널이 함께 나옵니다
  진행 단계(6~8칸) · 에이전트 흐름도 · 점수·위험도 게이지
```

**개발은 입력창으로, 검증·녹화는 `#play` 로 합니다.**

| | 쓰는 것 | 쓰는 때 |
|---|---|---|
| 개발 | 입력창에 직접 입력 | `pnpm dev` 로 띄우고 대화하며 만든다 |
| 검증·녹화 | `[데모 재생]` (`#play`) | 체크포인트, `pnpm smoke`, 영상 |

- `pnpm mock` 은 **고정 경로**입니다. 자유 입력을 보내면 *"고정 시나리오에서는 자유 대화가 반영되지 않습니다"* 안내가 옵니다. 고장이 아닙니다 — 대본을 보호하려고 일부러 막아 둔 것입니다
- **자유 대화를 보려면 `pnpm dev`** 로 띄웁니다 (`.env` 에 `USE_MOCK=0` · `BEDROCK_MODEL_ID` 필요, AWS 호출 발생). 상단 칩이 `Bedrock` 으로 바뀝니다
- **데스크톱 브라우저에 최적화**돼 있습니다 (최대 폭 1240px, 다크 테마)
- 모바일 앱처럼 보이는 것은 `.phone` 틀 안에 화면을 넣기 때문입니다
- 아이디어가 웹 서비스 형태면 `registry.ts` 에서 `layout: 'browser'` 로 바꿔 휴대폰 틀 없이 넓게 씁니다
- 개발 바(`.dev-bar`)는 사용자용이 아닙니다. 녹화 때 숨깁니다

### 스크립트로 kiro-cli를 돌릴 때

```bash
kiro-cli chat --no-interactive --trust-workspace \
  --trust-tools=read,write,shell,grep,glob --agent build "..."
```

`--trust-tools` 를 빼면 **파일을 쓰지 못합니다.** 비대화형에는 승인할 사람이 없어서 4번 재시도하고 포기합니다. 리허설에서 227초와 크레딧만 쓰고 파일이 안 생겼습니다.

## 4. 막혔을 때

| 상황 | 대응 |
|---|---|
| 에이전트가 엉뚱한 방향으로 갔다 | 새로 프롬프트 쓰지 말고 **`/rewind`** 로 되돌린다 |
| 세션이 느려졌다 | **`/compact`** |
| Bedrock throttling·오류 | 탐색은 `USE_MOCK=1` 로. 실제 호출은 체크포인트에서만 |
| 크레딧이 빠르게 닳는다 | 단순 작업은 `--effort low`. 리뷰는 `review` 에이전트(가벼운 모델) |
| 선정이 11:10을 넘긴다 | 1등 그대로 채택하고 넘어간다. 재실행은 1번까지만 |
| spec이 11:40을 넘긴다 | requirements를 버리고 **tasks만** 만든다. 데모 구간 표가 이미 요구사항 역할을 한다 |
| 15:30에 데모가 안 돈다 | 축소안 발동. `product.md` 의 축소안대로 구간을 줄인다 |
| 17:00에 기능이 미완성 | 미완성 구간을 mock으로 채운다. **데모는 완주해야 한다** |
| 라이브 호출이 불안하다 | 녹화를 `USE_MOCK=1` 로 한다. **mock 은 비상용**이다 (녹화 기본은 live) |

## 7. 알려진 함정

리허설에서 실제로 걸렸던 것들입니다.

| 함정 | 대응 |
|---|---|
| 레포 밖(상위 폴더)에서 Kiro 를 열면 에이전트·steering 이 안 붙고 엉뚱한 tasks 를 집는다 | 반드시 레포 폴더에서 `kiro-cli --agent build` |
| design 이 `beat_index` 로 단계를 나누거나, 입력 없는 start 에 400, `data` None 크래시 | `backend.md` "여러 에이전트·단계" 3줄. live 에서만 드러난다 |
| `device: "browser"` 녹화에서 카메라가 안 내려가 뒤 구간이 안 찍힌다 | capture 의 beat 마다 `focus` 에 보여줄 카드 선택자 |
| live 에서 카드와 다른 숫자가 나온다 | 정상(코드가 계산한 진짜 값). 슬라이드 숫자도 live 값으로 |
| `--no-interactive` 로 돌리면 파일을 못 쓴다 | `--trust-tools=read,write,shell,grep,glob` |
| 워크스페이스 신뢰 승인 전에는 훅·에이전트가 로드되지 않는다 | 전날 한 번 띄워 승인 |
| custom agent는 steering을 자동 로드하지 않는다 | `build.json` 의 `resources` 에 이미 넣어 뒀다. 새 에이전트를 만들면 똑같이 넣어야 한다 |
| `pnpm install` 이 esbuild 빌드 거부로 멈춘다 | `frontend/pnpm-workspace.yaml` 에 해결책이 들어 있다. `git pull` 만 하면 된다 |
| WSL·Linux에서 영상 녹화가 안 된다 | 시스템 라이브러리 부족(`libasound.so.2`). **발표 산출물은 담당3(macOS)이 만든다** |
| `deliverables/tools/puppeteer.json` 이 macOS Chrome 경로로 고정 | 같은 이유로 담당3 담당. 다른 사람이 해야 하면 `CHROME_PATH` 로 바꿔야 한다 |
| 포트·`#play` id·`data-beat` 를 바꾸면 검증과 녹화가 깨진다 | 바꾸지 않는다 |
| `pnpm mock` 에서 입력창에 쳐도 대화가 안 이어진다 | 고장이 아니다. 고정 시나리오는 입력을 보지 않는다. 자유 대화는 `pnpm dev` |
| 전송 중에 `#play` 를 잠그면 녹화가 종료를 잘못 읽는다 | `sending` 과 `running` 을 섞지 않는다 (입력창만 잠근다) |
