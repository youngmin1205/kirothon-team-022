## 4. 제출 폼용 문구 (17:35, 5분)

아래를 그대로 복사해 씁니다. 괄호 안은 출처입니다.

```

**한 줄 소개 (50자 이내)** (`product.md` 한 줄 소개)

```
사진 한 번, 기분 버튼 하나로 엄마·아빠에게 각자 맞는 안부를 보냅니다
```

**설명 (3~5줄)** — 아래 틀에 `product.md` 의 사용자·문제·해결을 넣습니다

```
누가: 부모님과 떨어져 사는 자취 직장인·대학생과, 앱을 설치하지 않는 그 부모님
문제: 부모님은 매일 "밥 먹었냐, 집에 들어갔냐"를 묻고, 자녀는 같은 답을 엄마·아빠에게 따로 치기 귀찮아 미루고, 그 사이 부모님은 걱정한다
해결: 사진 1~3장과 기분 버튼 하나면 끝난다. AI 는 사진으로 밥·귀가만 판정하고 기분은 자녀가 고른다. 받는 사람 프로필에 따라 공개 항목과 말투가 다른 메시지가 사람마다 만들어지고, 보내지 않기로 한 항목은 코드가 먼저 걸러내 모델에 넘기지 않는다. 부모님은 설치 없이 메시지 본문만 봐도 안부를 알고, 링크의 고정 버튼으로 답한다
데모: 사진 2장을 올리면(upload) AI 가 밥·귀가를 정리하고(judge), 엄마용·아빠용 메시지가 서로 다르게 만들어져(compose) 부모님 폰으로 가고, 엄마가 버튼으로 답하면 자녀 폰에 돌아온다(react·reply)
```

**기술 스택**

```
React 19 + Vite + TypeScript / Python + FastAPI /
Amazon Bedrock (Claude, Converse API) / Kiro CLI
```

**Kiro 활용** (`docs/kiro-usage-log.md` 에서 요약)

```
- spec 기반 개발: 요구사항 R1~R8 과 수락 기준을 먼저 만들고 task 11개에 L/BE/FE 라벨을 붙여 3명이 병렬 작업
- 수락 기준 → 테스트: 백엔드 64개 · 프런트 30개가 통과. "아빠 메시지에 기분 0건" 같은 기준이 실행 가능한 테스트로 남음
- live 버그를 코드가 아니라 수락 기준부터 고침: R2-3 보강 · R4-5 · R4-6 신설 후 테스트 추가
- steering 으로 팀 규칙 공유(공용 파일 소유권·포트·#play·data-beat 고정) → 체크포인트마다 smoke 통과
- 역할 에이전트 분리: build(개발) / review(읽기 전용 리뷰, 별도 세션)
